Một pipeline nhỏ nhưng đếm được từng dòng

DE biến dữ liệu nguồn thành dữ liệu đáng tin cho người sử dụng. Hãy nghĩ pipeline như dây chuyền có các trạm: đọc, kiểm tra, biến đổi và ghi. Mỗi trạm cần đầu vào/đầu ra rõ, số lượng đo được và cách xử lý khi lỗi. Dữ liệu bị loại vẫn cần lý do, không nên biến mất.

Từ vựng trước khi đọc tiếp

DataFrame
Bảng dữ liệu trong pandas; mỗi cột có tên và kiểu.
Validation
Kiểm tra dữ liệu theo rule đã được thống nhất.
Deduplication
Xử lý bản ghi trùng theo khóa và quy tắc chọn bản đúng.
Reconciliation
Đối soát count, key và tổng giá trị giữa các bước.

Đọc ví dụ theo từng bước

  1. Đọc 10.000 row; validation reject 300 nên còn 9.700.
  2. Dedup loại 200 row khác trong tập hợp lệ, còn 9.500.
  3. Kiểm tra 10.000 = 300 + 200 + 9.500 và lưu rejected reasons.
raw_count = 10_000
rejected_count = 300
duplicate_count = 200
curated_count = raw_count - rejected_count - duplicate_count
assert curated_count == 9_500
assert raw_count == rejected_count + duplicate_count + curated_count

Kết quả và cách hiểu: Các assert không báo lỗi vì các bucket disjoint trong ví dụ. Nếu một dòng vừa bị reject vừa tính là duplicate, phép đối soát này không còn đúng; cần thiết kế counter theo thứ tự xử lý.

Dễ nhầm: Null discount không mặc định là 0. Cần hỏi null là chưa biết hay không có giảm giá. CSV lớn phải đọc theo chunk và không gom toàn bộ chunk về RAM ở bước cuối.

Tự kiểm tra: 40 đơn khớp hai row customer C100; 960 đơn khác khớp một row. Merge ra bao nhiêu?

960 + 40 × 2 = 1.040. Khóa phía customer trùng gây nhân bản. Dùng validate='many_to_one' để phát hiện và sửa nguồn/rule chọn version trước khi tính revenue.

1. Python của Data Engineer khác gì script thông thường?

Một pipeline tốt không chỉ "chạy được". Nó phải đọc dữ liệu lớn hợp lý, có thể rerun an toàn, cấu hình được, test được, quan sát được và không làm lộ secret.

Luồng cơ bản:

Extract -> Validate -> Transform -> Load -> Audit

2. Đọc dữ liệu theo streaming/chunk

Không đọc toàn bộ file lớn vào RAM nếu không cần.

import csv

with open("orders.csv", encoding="utf-8", newline="") as file:
    for row in csv.DictReader(file):
        process(row)

Với pandas có thể dùng pd.read_csv(..., chunksize=100_000). Với dữ liệu phân tích lớn, ưu tiên Parquet vì có schema, column pruning và nén tốt hơn CSV.

3. Generator và iterator

Generator trả từng phần tử, giúp giảm memory:

def valid_orders(rows):
    for row in rows:
        if row.get("order_id") and float(row["amount"]) >= 0:
            yield row

Pipeline có thể nối nhiều generator: read → validate → transform → write.

4. Validation và error handling

Phân loại lỗi:

  • Transient: timeout, rate limit, network chập chờn → retry có giới hạn và exponential backoff.
  • Permanent/data error: sai schema, ngày không hợp lệ → không retry mù; đưa vào quarantine/dead-letter.
  • Programming error: bug code → fail fast, log stack trace, sửa và deploy lại.

Không dùng except Exception: pass. Log tối thiểu: run_id, dataset, step, record key, error code; tránh log password/token/PII.

5. Idempotency và incremental load

Rerun cùng input phải không tạo record trùng.

  • Ghi đè partition của đúng ngày.
  • MERGE/UPSERT theo business key.
  • Lưu batch_id, checksum hoặc source offset đã xử lý.
  • Watermark: chỉ lấy dữ liệu mới hơn mốc trước, nhưng cần lookback window để bắt late-arriving data.

Ví dụ watermark an toàn hơn:

last_success = 2026-09-20 00:00
next_extract_from = last_success - 2 hours
deduplicate after load

Chỉ cập nhật watermark sau khi target commit thành công.

6. Cấu hình, secret và môi trường

  • Config không nhạy cảm: file cấu hình hoặc environment variable.
  • Secret: secret manager/managed identity; không hard-code và không commit Git.
  • Tách dev, test, prod; không dùng chung bucket/schema đích.
  • Pin dependency và ghi rõ phiên bản runtime.

7. Logging và metrics

Log có cấu trúc dễ tìm kiếm:

logger.info(
    "batch_completed",
    extra={"run_id": run_id, "rows_in": 1000, "rows_out": 998, "bad_rows": 2},
)

Metrics quan trọng: duration, rows read/written/rejected, bytes, retry count, freshness lag. Alert cả khi job "thành công" nhưng zero record hoặc volume lệch mạnh.

8. Test pipeline

  • Unit test: một hàm transform với input nhỏ và expected output.
  • Contract/schema test: tên cột, kiểu, required field.
  • Integration test: đọc/ghi với database hoặc storage test.
  • Data quality test: unique, not null, range, relationship.
  • Rerun test: chạy hai lần, kết quả không nhân đôi.

Tách I/O khỏi business logic để hàm transform dễ test. Hàm nhỏ, input/output rõ ràng, type hint hợp lý.

10. Bài thực hành

Viết pipeline CSV → Parquet:

  1. Đọc theo chunk.
  2. Validate order_id, created_at, amount.
  3. Record lỗi ghi riêng cùng error_reason.
  4. Dữ liệu hợp lệ partition theo order_date.
  5. Log count và run_id.
  6. Chạy lại cùng file để chứng minh không trùng.

11. Checklist tự kiểm tra

  • File/connection luôn được đóng bằng context manager.
  • Timeout và retry chỉ áp dụng cho lỗi transient.
  • Không log secret hoặc PII thô.
  • Watermark chỉ advance sau khi thành công.
  • Có audit count và chiến lược quarantine/replay.

12. Schema-first thay vì "đọc gì cũng được"

Schema nên mô tả tên cột, type, nullable, domain, timezone và key. Infer schema tiện khi khám phá nhưng production có thể suy đoán khác giữa các batch (001 thành số 1, cột toàn null thành string...).

from dataclasses import dataclass
from datetime import datetime
from decimal import Decimal

@dataclass(frozen=True)
class Order:
    order_id: int
    customer_id: int
    created_at: datetime
    amount: Decimal

Tách parsing khỏi validation: parsing trả object hợp lệ hoặc error có code/cột/raw reference; không silently coerce giá trị mơ hồ.

13. Thời gian và timezone

  • Lưu timestamp sự kiện ở UTC khi có thể; giữ source timezone nếu cần audit.
  • Phân biệt event time, ingestion time và processing time.
  • Date partition theo business timezone cần ghi rõ, không dựa timezone của máy chạy.
  • DST làm một ngày có thể không đúng 24 giờ ở một số timezone.
from datetime import datetime, timezone

ingestion_ts = datetime.now(timezone.utc)

Không dùng naive datetime cho dữ liệu đi qua nhiều hệ thống.

14. Error record và quarantine

Một bad record hữu ích cần đủ để sửa/replay:

{
  "run_id": "run_20260922_01",
  "source_file": "orders_20260922.csv",
  "row_number": 18,
  "business_key": "order_99",
  "error_code": "INVALID_AMOUNT",
  "error_detail": "amount must be >= 0",
  "quarantined_at": "2026-09-22T03:00:00Z"
}

Raw payload nhạy cảm có thể lưu ở vùng bảo vệ thay vì log. Quarantine phải có owner, retention và quy trình reprocess; nếu chỉ tích tụ file lỗi thì chưa giải quyết vận hành.

15. Batch manifest

batch_id, source, extract_from, extract_to,
expected_files, received_files, source_rows,
valid_rows, rejected_rows, target_rows,
checksum, status, started_at, completed_at

Manifest là control plane cho dữ liệu: dùng phát hiện batch thiếu, ngăn process file dở, trace output và quyết định rerun.

16. Retry có kỷ luật

for attempt in range(max_attempts):
    try:
        return call_with_timeout()
    except TransientError:
        if attempt == max_attempts - 1:
            raise
        sleep(backoff(attempt) + jitter())

Phải có deadline tổng; nếu mỗi layer retry 3 lần, retry chồng có thể tạo rất nhiều request. Chọn một layer chịu trách nhiệm retry và phát metric số lần retry.

17. Worked example: incremental orders

  1. Đọc watermark thành công 10:00, chọn upper bound 11:00.
  2. Extract updated_at >= 09:50 AND updated_at < 11:00 để có lookback.
  3. Parse + validate; record lỗi vào quarantine.
  4. Deduplicate theo order_id, giữ updated_at mới nhất; tie-break bằng source sequence.
  5. MERGE staging vào target.
  6. Reconcile source/staging/target impacted keys.
  7. Commit watermark 11:00 sau thành công.

Nếu step 5 fail, watermark vẫn 10:00; rerun đọc lại overlap nhưng merge idempotent.

18. Câu hỏi có đáp án

  1. Tại sao Parquet nhanh cho analytics? Columnar, nén tốt, có schema và đọc đúng cột/row group cần thiết.
  2. Zero rejected rows có chắc tốt? Không; validator có thể chưa chạy hoặc rule quá lỏng.
  3. Khi nào fail toàn batch? Contract/schema lõi hỏng hoặc tỷ lệ lỗi vượt policy; record lỗi cô lập có thể quarantine.
  4. Watermark có thay backup không? Không; nó chỉ ghi tiến độ incremental.

Lab pandas và NumPy: tự tính trước, chạy sau

Cài trong môi trường project: python -m pip install pandas numpy. Ví dụ tạo dữ liệu trong memory; khi ghi Parquet cần thêm engine như pyarrow.

Đếm row khi merge

import pandas as pd
orders = pd.DataFrame({
    "order_id": ["O1", "O2", "O3"],
    "customer_id": ["C100", "C100", "C200"]
})
customers = pd.DataFrame({
    "customer_id": ["C100", "C100", "C200"],
    "city": ["Ha Noi", "Da Nang", "Hue"]
})
joined = orders.merge(customers, on="customer_id", how="left")
print(len(joined))  # 5 = 2 + 2 + 1
try:
    orders.merge(customers, on="customer_id",
                 how="left", validate="many_to_one")
except pd.errors.MergeError:
    print("Khóa customer phía phải chưa duy nhất")

O1 và O2 mỗi đơn khớp hai row C100 nên tạo bốn row; O3 tạo một. Không tự drop_duplicates để che lỗi: hai row có thể là version lịch sử cần chọn theo event time. Xử lý null join key có chủ đích: pandas có thể khớp null với null, khác phép so sánh NULL thông thường trong SQL.

Profile trước khi fillna

df = pd.DataFrame({
    "order_id": ["O1", "O2", "O2"],
    "amount": [100, 80, 80],
    "discount": [None, 0, 0]
})
print(len(df))                            # 3
print(df["order_id"].nunique())            # 2
print(df["discount"].isna().sum())         # 1
print(df["order_id"].duplicated().sum())   # 1

Null rate discount là 1/3. Chỉ fillna(0) khi xác nhận null nghĩa là không giảm giá; nếu chưa biết, giữ null và ghi trạng thái chất lượng để không khẳng định revenue đầy đủ.

File lớn hơn RAM

# Mẫu dùng file thật, giả định amount hợp lệ và là số nguyên.
total_amount = 0
for chunk in pd.read_csv(
    "orders.csv", usecols=["amount"],
    dtype={"amount": "int64"}, chunksize=100_000
):
    total_amount += int(chunk["amount"].sum())
print(total_amount)

chunksize trả DataFrame nhỏ nối tiếp, usecols giảm cột, dtype kiểm soát kiểu. Không concat mọi chunk ở cuối. Dedup toàn file cần state qua chunk hoặc database/storage trung gian; dedup riêng từng chunk bỏ sót bản sao nằm ở chunk khác.

Vectorization trên array

import numpy as np
quantity = np.array([2, 1, 3], dtype=np.int64)
price = np.array([50, 80, 20], dtype=np.int64)
amount = quantity * price
print(amount.tolist())    # [100, 80, 60]
print(int(amount.sum()))  # 240

Hai array cùng vị trí mô tả cùng dòng hàng. Vectorization để thư viện tính theo phần tử bằng implementation tối ưu. Vẫn cần kiểm tra shape, dtype và overflow.

Retry giải quyết lỗi gì?

Why are retries useful in a data pipeline?

Xem đáp án đúng và cách suy luận

They can automatically retry temporary failures

Retry thử lại thao tác bị lỗi tạm thời, chẳng hạn kết nối mạng gián đoạn vài giây. Nó có ích khi nguyên nhân có thể tự hết, có giới hạn lần thử và khoảng chờ. Nếu lần ghi đầu đã thành công nhưng mất response, sink phải idempotent để retry không tạo bản sao.

Vì sao LEFT merge thành 1.040 dòng?

df_orders has 1,000 rows. df_customers has one row per customer_id, except customer C100 appears twice. Exactly 40 orders belong to C100. What row count results from pd.merge(df_orders, df_customers, on='customer_id', how='left')?

Xem đáp án đúng và cách suy luận

1,040

960 đơn của khách khác mỗi đơn khớp một dòng, tạo 960 dòng. 40 đơn của C100 mỗi đơn khớp hai dòng customer, tạo 80 dòng. Tổng là 960 + 40 × 2 = 1.040. validate='many_to_one' giúp pandas phát hiện khóa phía customer không duy nhất thay vì âm thầm nhân dòng.

Tính output sau validate và dedup

A raw file contains 10,000 rows. Validation rejects 300 rows, and deduplication removes another 200 duplicate rows from the valid set. What curated row count should the validation summary expect?

Xem đáp án đúng và cách suy luận

9,500

Validation loại 300 dòng từ 10.000, còn 9.700 dòng hợp lệ. Dedup loại thêm 200 dòng trong tập hợp lệ đó, nên curated còn 9.700 − 200 = 9.500. Hai nhóm loại không chồng lên nhau trong đề này; báo cáo nên giữ cả hai counter.

CSV 20 GB trên máy RAM 8 GB

A 20 GB CSV file must be processed on a machine with 8 GB RAM using pandas. Which approach is most appropriate?

Xem đáp án đúng và cách suy luận

Read the file in chunks and/or restrict columns and dtypes, processing incrementally

Đọc theo chunksize giúp xử lý từng phần; usecols và dtype giảm dữ liệu nạp vào bộ nhớ. CSV parse thành object có thể chiếm RAM lớn hơn dung lượng file. Không nối lại mọi chunk ở cuối; các phép dedup/aggregate toàn cục cần state hoặc lưu trữ trung gian phù hợp.

Null không tự động bằng zero

A sales feed contains nulls in discount_amount. What is the safest engineering response?

Xem đáp án đúng và cách suy luận

Confirm the business meaning of null, apply the agreed rule, and document the treatment

Null có thể là chưa biết, không áp dụng hoặc dữ liệu chưa đến. Zero khẳng định giá trị bằng không. Cần xác nhận với business rồi áp quy tắc và ghi lại, vì thay null bằng zero không đúng nghĩa sẽ làm lệch doanh thu hoặc discount.

Xử lý record không hợp lệ

A data job encounters invalid records that the agreed rule allows to be rejected. Which behavior is best?

Xem đáp án đúng và cách suy luận

Separate rejected records, record counts/reasons, and continue processing valid records when the rule allows

Khi policy cho phép tiếp tục, tách record lỗi vào quarantine cùng lý do, run_id và tham chiếu nguồn. Dòng hợp lệ vẫn được xử lý, nhưng tổng count phải đối soát được. Nếu vi phạm schema lõi hoặc vượt ngưỡng lỗi, policy có thể yêu cầu fail toàn batch.

NumPy và vectorization

Xem đáp án đúng và cách suy luận

Use vectorized array operations for repeated numerical calculations

Vectorization biểu diễn phép tính trên cả array như quantity * price để thư viện xử lý bằng vòng lặp tối ưu bên dưới. Cách này giảm overhead lặp từng phần tử bằng Python. Dữ liệu cần kiểu số phù hợp và phải kiểm tra shape, dtype, overflow.

Source-to-target mapping

What is the primary purpose of a source-to-target mapping?

Mapping mô tả mỗi cột đầu ra lấy từ đâu, đổi kiểu hay tính toán thế nào, có default gì và kiểm tra bằng rule nào. Ví dụ source.total_text → target.amount decimal, lỗi parse vào quarantine. Đây là hợp đồng triển khai giúp giảm suy đoán khi viết code.

Data profiling đo gì?

Profiling mô tả dữ liệu bằng row count, null rate, distinct count, min/max và phân bố. Ví dụ customer_id lặp hay amount âm là bằng chứng để thiết kế rule. Metric CPU/RAM mô tả hệ thống chạy, không mô tả chất lượng tập dữ liệu.

Nguồn đổi tên cột âm thầm

A source silently renames a critical column. The pipeline still runs but begins writing nulls to the curated layer. Which control best reduces the chance of this becoming silent bad data?

Xem đáp án đúng và cách suy luận

Validate the incoming schema and enforce critical-field data-quality tests so the run fails on breach

Schema validation phát hiện field bắt buộc bị mất trước khi transformation tạo ra NULL. Critical-field tests ở curated là lớp kiểm tra bổ sung. Khi vi phạm contract quan trọng, fail/chặn publish để tránh dữ liệu xấu trông như một run thành công.
